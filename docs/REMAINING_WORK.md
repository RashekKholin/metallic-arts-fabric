# Ordered acceptance and future work

The 1.0.0-rc.2 candidate implements the requested release engineering and a large expansion of gameplay. It is not a claim that every possible canonical system or every external acceptance condition is finished. Current results are in RELEASE_VALIDATION.md; detailed new behavior is in RELEASE_CANDIDATE.md.

## Before declaring stable 1.0

1. **Authenticated remote multiplayer:** two or more real licensed accounts on a remote online-mode dedicated server. Test join/rejoin, dimension changes, death, every private payload, claims, donor/memory consent, charge transfer and body dependencies under measured latency/loss. The automated ordinary two-client loopback test cannot impersonate licensed accounts or certify remote hosting.
2. **Extended soak and survival acceptance:** run representative hours-long sessions with active powers, NPC combat, projectiles, temporal machines, chunk unload/reload and repeated saves. Record tick percentiles, worst pauses, memory, ledger/file growth, bandwidth, client interpolation and exact resource conservation. Compare gameplay acquisition costs through an ordinary non-operator playthrough. Automated fixtures are regression evidence, not player balance approval.
3. **Platform acceptance:** require the native server matrix and Linux graphical CI to pass. Check real Linux/macOS graphics, keyboard/narrator behavior, scaling and driver combinations outside software-rendered CI. Reproduce install/upgrade using release jars, not just development classes.
4. **Localization and accessibility review:** complete and review Spanish UI/tutorial/status coverage; English fallback is currently intentional. Test a real screen reader, custom keybindings, minimum GUI size, overload/particle/sound settings and non-English variable labels across every menu. Do not count English copies as translated entries.
5. **Rights and distribution:** source licensing is resolved as All rights reserved. Review third-party branding/fan-use permissions separately, and review actual current Modrinth rules/disclosures before submission. No legal clearance or Modrinth approval is implied by working code. Obtain permission before incorporating outside contributions that cannot later be relicensed.
6. **Stable packaging:** close reproducible bugs, freeze balance/scope, retain published candidate checksums and evidence, obtain explicit acceptance of known limits, then create a new immutable stable version. Never overwrite an existing tag's jars with a different build.

## Future expansions after those gates

1. **Standard Arts depth:** explicit adapters for additional evidence-backed Investiture detection, competing emotion/NPC awareness, machine/vehicle clocks, supported survival physiology and protected Fortune opportunities. Maintain finite payments, bounded scans and opt-in integration. General redstone/random/scheduled ticks and whole-world time remain global until separately designed/tested.
2. **Spiritual and equipment depth:** richer Copper organization/sharing permissions, typed social/language adapters, more unsealed-core carriers and an optional swallowed-source compounding interface/residual recovery. Preserve canonical-once source accounting, Identity and independent charge. Human knowledge, universal translation, destiny and identity impersonation are not inferred abilities.
3. **Constructs/Hemalurgy:** research additional placements, species, body forms, multiple-power extraction and long-term psychological consequences. Extend actual source provenance/dependencies rather than giving templates unlimited powers. Unpublished anatomy and real-world harm are not simulated by guesswork.
4. **Authored content:** larger structures, named factions/NPC behaviors, branching quests and discoveries, more original audio/animation, and multiplayer progression campaigns. The current camps, reputation and advancement path are a finite baseline, not a completed narrative campaign.
5. **God metals:** add each additional published metal/alloy independently after direct-source research, precise ownership/cost design and tests. Keep pure Atium distinct from Era-one alloy material. Unknown effects and the unpublished Excisor process remain explicitly unresolved; no fabricated ability is presented as canon.
6. **Integration maintenance:** test new claim/PvP mods and published dependency updates, add migration fixtures for each persisted schema change, monitor real server reports and keep immutable releases/recovery guidance current.

An outside account, platform approval, unpublished canon or hardware result cannot be replaced by a passing unit test. These open gates remain visible rather than being marked complete automatically.
